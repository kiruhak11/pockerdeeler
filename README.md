# Poker Dealer Desk

Nuxt 4 приложение для дилера покера с двумя режимами:

- `Local Mode`: локальный калькулятор раздач (без backend, `localStorage`).
- `Online Room Mode`: онлайн-комнаты с серверно-авторитетной логикой, PostgreSQL и WebSocket-синхронизацией.

## Технологии

- Nuxt 4
- Vue 3 Composition API
- TypeScript
- SCSS
- Pinia
- Nitro API + WebSocket
- Prisma ORM
- PostgreSQL
- Docker / Docker Compose
- PgBouncer (production-like)

## Что уже реализовано

### Навигация, сохранённые места и удаление комнаты

- Нижняя навигация: главная, столы (`/rooms`), создание комнаты, профиль. Каталог открытых и закрытых столов больше не занимает главную.
- Для игрока с аккаунтом есть два разных действия: **«Отойти, сохранив место»** и **«Выйти полностью»**. Переход через нижнее меню с игрового экрана также предлагает сохранить место.
- Временный выход хранится в PostgreSQL (`players.is_away`), а не только в браузере. Место занимает слот в комнате. Игрок пропускает новые раздачи и блайнды до возвращения. До вскрытия обычная рука сбрасывается; ва-банк и право на выигрыш на вскрытии сохраняются. Внесённые ставки не исчезают. Undo не пересекает изменение присутствия.
- **«Вернуться к столу»** на главной и во вкладке «Столы» восстанавливает место по токену аккаунта, в том числе после входа на другом устройстве. Восстановление не меняет стек и не возвращает сброшенную руку в текущую раздачу. Обычные новые входы по-прежнему проверяют пароль, вместимость и поздний вход.
- Полный выход освобождает место и имя, отзывает токен комнаты. После него и после кика восстановление старого места запрещено. Незавершённый ва-банк рассчитывается отдельно. Пока за аккаунтом сохранено место в активной игре, ежедневный бонус и вход с этим балансом в другую комнату недоступны.
- Комната с сохранёнными местами не считается пустой. После полного выхода последнего игрока она удаляется автоматически.
- Дилер может **«Удалить комнату и выйти»**, подтвердив действие. Сервер блокирует комнату в транзакции, отменяет незавершённую раздачу, возвращает её взносы аккаунтам и закрывает WebSocket всех участников. Уже рассчитанные выигрыши сохраняются. Повторный запрос не зачисляет деньги повторно. Гостевые стеки и история удаляются вместе с комнатой.
- Служебная очистка старых комнат при релизе выполняется отдельно, после резервной копии, без изменения балансов аккаунтов: устаревшие дубли мест нельзя использовать для пересчёта текущих балансов.

API: `POST /api/auth/rooms`, `POST /api/rooms/:code/away` и `/resume` используют `{ token }` аккаунта; полный выход `/leave` поддерживает `{ authToken }` либо токен участника; `/delete` требует `{ dealerSecret }`. WebSocket закрывается с кодом `4004` при удалении комнаты, `4005` при сохранении/передаче места другому клиенту.

### Local Mode

- Создание игры, настройка игроков, стеков и мест.
- Автоназначение мест, если позиция не задана.
- Настройки стола: `small blind`, `big blind`, быстрые повышения.
- Автопроставление малого/большого блайнда при старте игры и новой раздачи.
- Полный цикл действий: `check`, `bet`, `call`, `raise`, `fold`, `all-in`.
- Undo последнего действия на основе snapshot.
- История раздач.
- Сохранение/восстановление из `localStorage`.
- Запрет изменения состава игроков после старта игры.

### Online Room Mode (MVP)

- Создание комнаты (`/api/rooms/create`) и короткого room code.
- Вход игроков по коду (`/api/rooms/[code]/join`).
- Серверная проверка токенов игрока и `dealerSecret`.
- Серверно-авторитетная обработка покерных действий в транзакциях.
- Идемпотентность действий через `clientRequestId` + уникальный индекс.
- Snapshot в БД перед действием/распределением банка.
- Undo дилера через восстановление snapshot.
- Realtime обновление состояния комнаты по WebSocket (`room_state_updated`).
- Хранение комнат, игроков, раздач, действий и истории в PostgreSQL.

### Бай-ин, Прогнозы И Возврат

- Баланс аккаунта разделён на свободный кошелёк (`user_wallets`) и стек конкретного стола. При входе игрок выбирает бай-ин в диапазоне дилера; остаток остаётся в кошельке. Повторный `clientRequestId` не списывает средства повторно.
- Между раздачами дилер может разрешить пополнение стека до максимального бай-ина. Сервер проверяет владельца аккаунта, доступный кошелёк и отсутствие активной раздачи.
- После первого вылета подтверждённый участник с аккаунтом получает отдельные прогнозные очки. Они не являются балансом аккаунта и не могут целиком вернуться за стол.
- В следующей раздаче выбывший участник прогнозирует единоличного победителя основного банка. Один прогноз можно сделать на любой улице до завершения торговли, включая промежутки открытия общих карт. «Дождаться флопа / тёрна / ривера» сохраняет личный выбор зрителя в sessionStorage и ничего не списывает. Игра никогда не ждёт прогнозов.
- Новые рынки используют `fixed_odds`: текущая оценка обновляется после действий, выхода игроков, открытия улицы и новых прогнозов. Это игровая модель публичного поведения и распределения прогнозов, НЕ вероятность, рассчитанная по картам. Более поздняя улица уменьшает премию раннего прогноза (1 / 0.95 / 0.90 / 0.85). Коэффициенты ограничены 1.01–25.00.
- При принятии сохраняются целые сотые коэффициента, улица и выплата `floor(stake * acceptedOddsHundredths / 100)`. Дальнейшие изменения котировок не меняют билет. Устаревшая ревизия отклоняется без списания, зритель подтверждает новый коэффициент. Максимальная суммарная выплата на одного победителя полностью резервируется транзакцией из фонда комнаты; при нехватке резерва новая ставка отклоняется. Остатки и округление возвращаются в фонд, фишки не создаются.
- Активные игроки не получают коэффициенты и чужие прогнозы. Персональный прогнозный баланс загружается только по токену аккаунта; дилер видит отдельную административную сводку.
- Приём закрывается атомарно с окончанием торговли (либо последним фолдом), до определения победителя. Split основного банка, отмена раздачи, удаление комнаты, undo действия при принятых прогнозах или ручной `void` дилера возвращают все поставленные очки ровно один раз. Старые рынки `pari_mutuel` сохраняют прежний расчёт без изменения ранее принятых обязательств; новые правила действуют со следующей раздачи. Параметр `gracePeriodSeconds` оставлен для совместимости старых рынков, но больше не задерживает открытие флопа.
- Дилер и участники получают модальные подсказки для открытия трёх карт флопа, одной карты тёрна и одной карты ривера. Дилер подтверждает физическое открытие; уведомление об открытой улице закрывается через 3 секунды. Участники не могут открыть улицу сами.
- Вернуться за стол можно только между раздачами, только на чистую прибыль сверх стартовой выдачи и в пределах заданного дилером диапазона. Поддерживаются ручное подтверждение и автоматический возврат.
- Новые аккаунты после блокировки состава ожидают решения дилера. Их кошелёк не списывается до одобрения; дилер может связать новый аккаунт с прежним участником вечера без новой стартовой выдачи.
- Все переводы записываются парными ledger-записями с `transferId`; системная эмиссия помечается отдельно. PostgreSQL `CHECK`, уникальные ключи, row lock и транзакции защищают от отрицательных балансов, двойного клика и конкурентного расчёта.
- На вход, создание комнат, прогнозы, возвраты и решения по составу действует rate limit. WebSocket поддерживается heartbeat-сообщениями для стабильной работы через Nginx.

## Обновление Лобби И Аккаунта

- На главной есть список открытых и закрытых комнат. Закрытые видны в списке, но требуют пароль при входе, в том числе по приглашению. В базе хранится только scrypt-хеш пароля; публичный список не содержит игроков, чата или секретов.
- При создании выбирается состав: аккаунты, гости или смешанный стол. Аккаунт использует свой баланс, гость получает стартовый стек комнаты. Одновременно использовать баланс аккаунта за несколькими столами нельзя.
- Кнопка «Выйти из комнаты» освобождает место и имя. Закрытие вкладки или перезагрузка не означают выход. Внесённые фишки остаются в банке; вышедший all-in сохраняет право на выплату до расчёта. Финансовые записи остаются в истории, но карточки вышедших игроков скрыты.
- Поздний вход означает ожидание следующей раздачи, а не немедленное участие в текущей.
- Префлоп, флоп, тёрн и ривер учитываются сервером. После завершения торговли дилер видит уведомление и подтверждает открытие 3/1/1 карт. До подтверждения действия заблокированы. Если остался один участник раздачи, открывать карты не требуется. При all-in без дальнейшей торговли подтверждаются все оставшиеся улицы.
- После открытия карт или изменения состава undo не пересекает эту границу; после выплаты отмена запрещена. Это исключает восстановление уже покинувшего комнату игрока и повторную трату выплаченных фишек.
- Каждый основной/побочный банк имеет собственный выбор победителей. Непокрытая ставка возвращается отдельно. Остаток при делении выдаётся по порядку мест. Логика неполных all-in повышений основана на [правилах Poker TDA](https://www.pokertda.com/view-poker-tda-rules/).
- В профиле «Получить +5 000» прибавляет фишки в свободный кошелёк один раз в **24 часа**. Бонус не обнуляет накопления, не меняет уже внесённый стек и запрещён во время активной игры или ожидания выплаты. Старый endpoint сброса использует тот же лимит, а не даёт обходное пополнение.
- WebSocket и чтение состояния требуют токен участника или секрет дилера. Повторный вход отзывает старое подключение. Ревизии состояния защищают клиент от запоздавших ответов. Поддерживается один процесс приложения; Redis-масштабирование пока не реализовано.
- Старые активные раздачи без `betting_state` можно завершить вручную. Полное отслеживание улиц начинается с новой раздачи. Миграции аддитивные, аккаунты и существующие комнаты сохраняются.

### Безопасная Выкладка

Перед обновлением сохраните `pg_dump -Fc`, исходники и `.env` в каталоге с правами 700, а текущий Docker-образ пометьте rollback-тегом. Соберите новый образ отдельно. Миграции запускайте через `DIRECT_DATABASE_URL`, приложение подключайте через `DATABASE_URL` к PgBouncer. Не пересоздавайте PostgreSQL и не удаляйте volumes. После обновления проверьте `/api/health`, HTTPS и авторизованное WebSocket-подключение. Для отката переключите только приложение на предыдущий образ; новые колонки совместимы со старой версией. Не откатывайте базу без необходимости: это потеряет действия, совершённые после резервной копии.

### Зачем PgBouncer

PgBouncer уменьшает нагрузку на PostgreSQL и стабилизирует большое число коротких подключений.
В проекте используется `pool_mode=transaction`.

### Prisma + PgBouncer

- Приложение подключается через `DATABASE_URL` (PgBouncer).
- Миграции выполняются через `DIRECT_DATABASE_URL` (прямой PostgreSQL).
- В `DATABASE_URL` для Prisma добавлен `pgbouncer=true`.

## Инварианты покер-логики

- Стеки игроков не уходят в минус.
- Банк формируется из внесённых фишек (`totalCommitted`).
- Распределение банка не теряет фишки.
- Поддержаны all-in и side-pots (вынесено в расчётный модуль).
